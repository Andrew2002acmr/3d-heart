# Интерактивный прототип: КТ, маска и 3D

Локальное приложение на **PySide6 + PyVistaQt / VTK**. Оно читает исходные NIfTI и уже сохранённые VTP. Marching cubes, сглаживание и упрощение при открытии окна **не запускаются**. Работа выполнена в `feature/interactive-viewer`, созданной от `feature/geometry-validation`; слияния с `main` нет.

## Запуск

В существующем проекте с установленными зависимостями:

```powershell
cd D:\codexProjects\3d-hearts
.\.venv\Scripts\python.exe -m heart3d gui
```

Если зависимости этой ветки ещё не установлены, один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

Можно явно задать каталоги и первый случай:

```powershell
.\.venv\Scripts\python.exe -m heart3d gui --data data\imagechd --results outputs\validation_20260928_120859_296 --case ct_1003
```

По умолчанию используются `data/imagechd` и `outputs`. Нужны пары `*_image.nii.gz` / `*_label.nii.gz` (также поддерживаются `.nii`) и результаты прежнего построения: `report.json` с каталогом `meshes`. Постобработка необязательна. Данные и модели не входят в Git. Прежняя команда `heart3d view` сохранена.

## Что реализовано и как управлять

- Список исследований собирается из найденных пар файлов; ID четырёх проверенных случаев в код не зашиты. Загрузка работает в одном фоновом потоке; во время чтения выбор другого случая временно отключён.
- Одновременно видны axial, coronal и sagittal. Для каждого вида — ползунок, числовой индекс с нуля, флажок маски и её непрозрачность. `42 %` означает 42 % цвета метки и 58 % КТ. Числа относятся к текущей сетке вокселей, а не к миллиметрам.
- В левой панели можно отключить всю маску на КТ, скрыть отдельную структуру сразу в 2D/3D, выбрать её вариант поверхности и изменить непрозрачность в 3D. `100 %` — непрозрачная поверхность. Для просмотра камер можно скрыть MYO.
- Цвета LV, RV, LA, RA, MYO, AO, PA берутся из общей палитры `heart3d/labels.py`. На освещённой поверхности видимый оттенок дополнительно зависит от освещения.
- В 3D: ЛКМ — вращение; колесо — масштаб; средняя кнопка или Shift+ЛКМ — перемещение; кнопка «Сброс камеры» — возврат к изометрии. Есть виды с шести сторон. `R* / L* / A* / P* / S* / I*` относятся **только к заголовку**; это не подтверждённые направления пациента.
- «Плоскости срезов в 3D» включает три полупрозрачных четырёхугольника. Их позиции меняются вместе с индексами срезов; к координатам один раз применяется полный affine. Эти плоскости показывают положение сечения, без текстуры КТ.
- Окно интенсивностей КТ настраивается общими минимумом и максимумом. Начальные значения берутся из сохранённого отчёта, при их отсутствии — из выборки КТ. Значения файла не объявляются HU.
- Информационная панель показывает ID, размер, число структур, отсутствие меток и предупреждения сохранённого отчёта. У `ct_1003` MYO помечен «нет» и отключён; остальные шесть структур доступны.

## Как выбираются готовые модели

`report.json` сопоставляется с текущими КТ и маской по SHA-256, размеру сетки, единицам и affine. Среди совпавших отчётов приоритет имеют отчёты с явно записанной политикой нормалей, затем более свежий файл. Путь выбранного отчёта виден в панели. Для однозначного выбора конкретного прогона ограничьте `--results` его каталогом.

VTP проверяется на читаемость, треугольные ячейки, конечные координаты, соответствие количества точек/треугольников отчёту и единицам, если поле единиц записано. Если VTP недоступен, КТ и маска продолжают отображаться с предупреждением. Это лёгкая проверка загрузки, а не повторный полный аудит топологии или криптографическая аттестация VTP; для полного аудита сохранённых результатов остаётся `scripts/verify_saved_run.py` из [предыдущего этапа](run_validation_2026-09-29.md).

**Original всегда выбран первым.** Для доступных экспериментов:

- `Smoothed` читает `taubin.vtp`;
- `Simplified` читает `decimate50.vtp`;
- необходимы совпадение SHA-256 маски, единиц и точное равенство точек/граней экспериментального `original.vtp` выбранной исходной поверхности;
- сохранённые счётчики граничных, неманифолдных, несогласованно ориентированных рёбер и вырожденных треугольников не должны увеличиваться; отсутствующие метрики блокируют вариант;
- `taubin_decimate50` не предлагается: ранее комбинация создавала новые дефекты.

Это правило допуска по **сохранённым метрикам**, не доказательство анатомической точности. Известные дефекты Original не скрываются и не ремонтируются.

## Архитектура

| Файл | Ответственность |
|---|---|
| `heart3d/volume.py` | Существующая загрузка NIfTI и проверка совместимости сеток |
| `heart3d/labels.py` | Общие ID, названия и палитра |
| `heart3d/interactive/data.py` | Поиск случаев/отчётов, чтение VTP и допустимых вариантов |
| `heart3d/interactive/state.py` | Состояние просмотра, RGB срезов, координаты плоскостей; без Qt |
| `heart3d/interactive/slices.py` | Qt-панели срезов и масок |
| `heart3d/interactive/scene.py` | Встроенная сцена PyVista, камера, акторы и плоскости |
| `heart3d/interactive/window.py` | Компоновка окна, управление и поток загрузки |
| `scripts/check_interactive_viewer.py` | Проверка окна на уже сохранённых реальных случаях |

Интеграция использует [`QtInteractor`](https://qt.pyvista.org/usage.html) с PySide6. Зависимости зафиксированы: PySide6 6.11.2, PyVistaQt 0.13.1, QtPy 2.4.3; прежние версии NiBabel/PyVista/VTK сохранены.

## Проверка

Проверены случаи из `outputs/validation_20260928_120859_296`:

| Случай | Размер | Метки / Original | Дополнительные варианты |
|---|---|---|---|
| ct_1001 | 512 × 512 × 221 | 7 / 7 | Smoothed и Simplified: LV, MYO, PA |
| ct_1002 | 512 × 512 × 137 | 7 / 7 | Нет сохранённых экспериментов |
| ct_1003 | 512 × 512 × 206 | 6 / 6, MYO отсутствует | Нет сохранённых экспериментов |
| ct_1004 | 512 × 512 × 344 | 7 / 7 | Smoothed и Simplified: LV, MYO, PA |

Проверка использует настоящее Qt-окно: последовательно выбирает случаи, меняет индексы включая крайние, маску, её непрозрачность, видимость структур, варианты VTP, камеру и плоскости. Сохраняет снимки окна/3D, JSON с источниками и доступными вариантами. Сравнивает хеши исходных NIfTI после просмотра. Это программная проверка связей элементов управления и рендеринга; анатомическую экспертизу она не заменяет.

Найденная при просмотре снимков ошибка: `PyVista.clear()` удаляет освещение, после смены случая модели выглядели плоскими. Восстановление источников света добавлено после каждой очистки сцены, сохранность освещения покрыта графическим тестом. Геометрия VTP при этом не изменяется.

Финальный локальный прогон 29.09.2026: все четыре случая прошли проверки, хеши восьми исходных NIfTI не изменились. Просмотрены снимки трёх срезов и 3D каждого случая. [Машиночитаемый протокол](validation/interactive_viewer_check.json); полные снимки находятся локально в `outputs/interactive_viewer_check_final_20260929`. Загрузка до готовности окна заняла соответственно 12,35 / 6,36 / 8,67 / 19,01 с на этой машине; это наблюдение одного прогона с возможным файловым кэшем, а не гарантированная производительность.

Локально прошли **31 тест**: 29 неграфических и 2 графических. Старые 24 проверки сохранены; новые проверяют загрузку произвольного ID, отсутствие MYO/VTP, устаревший отчёт, необязательные метаданные, допуск вариантов, общую палитру и видимость, применение affine к плоскостям и связи Qt-элементов. GitHub Actions запускает 29 неграфических тестов; Qt/VTK-рендер проверяется локально. Предупреждения NumPy/scikit-image об устаревающем API остаются, тесты проходят.

Повторение тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
$out = 'outputs\viewer_check_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
.\.venv\Scripts\python.exe scripts\check_interactive_viewer.py --cases ct_1001 ct_1002 ct_1003 ct_1004 --out $out
```

Папка `--out` должна быть новой или пустой. Скрипт открывает окно и сам переключает элементы управления; дождитесь завершения. Готовые поверхности только читаются. Снимки и JSON этой проверки остаются в игнорируемой папке `outputs`.

## Ограничения и следующий этап

Физический масштаб и полная ориентация пациента по-прежнему **не подтверждены**. Противоречие A/P, найденное ранее, не исправляется поворотом осей. Существующий загрузчик приводит представление к осям заголовка без интерполяции; у четырёх проверенных файлов RAS уже записан в заголовке. Исходные NIfTI и affine на диске не меняются. При наклонной или скошенной сетке показываются родные плоскости массива с предупреждением, а не вычисленные анатомические MPR.

Все исходные компоненты и топологические дефекты сохранены: в частности, у MYO `ct_1001` / `ct_1004` остаются 12 / 3 неманифолдных ребра. Изменение прозрачности не исправляет эти дефекты. Метрики в mm/ml, инструменты измерений и клинические выводы в интерфейс не добавлены.

Прототип держит в памяти один выбранный случай и его доступные варианты VTP; скорость загрузки/вращения зависит от размера модели и видеодрайвера. Переключение случаев перечитывает файлы. Отмена текущего чтения и кэш нескольких исследований не реализованы; закрытие окна во время загрузки ожидает её окончания. Для GUI нужен графический контекст VTK; проверена Windows-среда. Поле предупреждений прокручивается.

Связанные плоскости реализованы без КТ-текстуры и без выбора общей точки щелчком по срезу. Следующий небольшой шаг после показа научруку — собрать обратную связь об удобстве срезов и выбранных видах. Научный приоритет остаётся прежним: подтвердить физическую геометрию по источнику и вместе со специалистом проверить спорные компоненты.

## Только КТ, без маски

Откройте одну или несколько уже собранных 3D NIfTI серий:

```powershell
python -m heart3d gui --ct <volume_1.nii.gz> --ct <volume_2.nii.gz>
```

Повторяющийся `--ct` включает отдельный CT-only режим: axial/coronal/sagittal,
переключатель томов, листание срезов и общие минимум/максимум окна яркости.
Маски, saved surfaces и model checkpoints не читаются; inference не запускается.
CT_001/CT_002 — локальные aliases порядка выбора, не PatientID.
Исходные файлы только читаются. Допускаются NIfTI после проверенного DICOM import;
это не импорт несортированного DICOM каталога непосредственно в GUI.
Lossless перестановка/разворот осей по affine сохраняют voxel values;
для oblique acquisition показываются родные reoriented planes без resampling.
Внутренний zero display buffer не является segmentation или ground truth,
не сохраняется на диск и не предлагается как результат.

Пути данных задаются через CLI. Для текущих двух исследований подготовленные
volumes находятся во внешнем data root в
`external_ct/audit_v1/prepared/case_001/series_004/ct.nii.gz` и
`external_ct/audit_v1/prepared/case_002/series_010/ct.nii.gz`.
