# Первый прогон ImageCHD — 28 сентября 2026

> Исторический отчёт первого этапа. Последующая [проверка четырёх случаев](geometry_validation.md) уточнила связь ключей XLSX, выявила противоречие A/P в независимом просмотрщике и исправила переориентацию внутренних оболочек при вычислении нормалей. Приведённое ниже «согласование нормалей» относится к ранней реализации; для новых измерений используйте текущую версию и материалы второго этапа.

## Результат этапа

Цепочка `файлы → готовая маска → mesh → 3D` выполнена на реальных `ct_1001_image.nii.gz` и `ct_1001_label.nii.gz`. Получены 9 КТ-срезов с разметкой, 7 VTP-поверхностей, JSON-отчёт и интерактивный PyVista viewer с вращением, масштабированием и независимой видимостью структур.

Исходная папка проекта была пустой. С Kaggle загружен один случай и две сопроводительные таблицы. Полный набор не загружался; его каталог содержит 110 КТ и 110 масок. CRC32 извлечённых файлов проверены, SHA-256 пары записаны в `data/imagechd/provenance.json` и выходном отчёте.

|---|---|---|
| Размер | 512 × 512 × 221 | 512 × 512 × 221 |
| Тип исходных данных | int16 | int8 |
| pixdim / spacing affine | 1, 1, 1 | 1, 1, 1 |
| Единицы | unknown | unknown |
| Оси по заголовку | RAS | RAS |
| qform_code / sform_code | 0 / 1 | 0 / 1 |
| Начало координат по sform | 1, 1, 1 | 1, 1, 1 |
| Диапазон | 0…4095 | целочисленные 0…7 |

Affine одинакова и равна единичной матрице с переносом `(1, 1, 1)`. qform не активна; её отличие от sform не считается конфликтом двух активных преобразований. Совпадение сеток позволяет корректно наложить маску на КТ. Оно не подтверждает достоверность исходного физического масштаба и ориентации.

## Найденные проблемы

1. **Физический масштаб не подтверждён.** В NIfTI нет единиц, spacing равен 1. В `imagechd_dataset_image_info.xlsx`, `Sheet1`, строка 1 содержит `idx=1` (B1), `PixelSpacing=0.29102, 0.29102` (J1:K1), `calculate_z_thick=0.75` (M1). Это потенциальный источник истинного масштаба, но таблица использует исходные idx, а имена файлов — другие ID. Правило сопоставления не установлено. Нельзя просто назначить строку 1 файлу `ct_1001` и выдать результат за проверенные миллиметры. Кроме того, нужно подтвердить, что `calculate_z_thick` — межсрезовое расстояние именно экспортированной серии, и исключить ресэмплинг при подготовке NIfTI.
2. **Анатомическая ориентация не подтверждена.** `RAS` следует из sform, однако простая единичная матрица не доказывает сохранность направлений пациента. На срезах позвоночник расположен со стороны больших индексов j, что вызывает сомнение в достоверности направления A по заголовку. Это наблюдение для проверки, не основание автоматически переворачивать данные. Нужны DICOM-направления/документированная конвертация или сверка с анатомическими ориентирами в независимом просмотрщике. В текущем viewer оси подписаны как направления из заголовка.
3. **Интенсивности нельзя уверенно назвать HU.** Диапазон 0…4095 может отражать предобработку или смещение шкалы. Автоматический сдвиг на −1024 не выполняется. Срезы используют диапазон интенсивностей исходного файла.
4. **Мелкие компоненты маски.** LA имеет 9 компонент, MYO — 3, PA — 7 (26-связность). Вне крупнейшей компоненты остаются соответственно 64, 67 и 77 вокселей. LV, RV, RA, AO имеют по одной компоненте. Все сохранены: необходима визуальная оценка до любого удаления.
5. **Топология MYO.** У mesh миокарда 12 неманифолдных рёбер и 0 граничных рёбер. У остальных поверхностей обе величины равны 0. Это отдельная проблема от числа компонент. Автоматического заполнения отверстий, сглаживания или ремонта нет. Самопересечения не проверялись.
6. **Большие поверхности и ступенчатость.** Всего 2 655 960 треугольников. Сохранено полное разрешение маски; на границах заметна дискретность вокселей. Упрощение и сглаживание должны быть отдельным измеряемым экспериментом, с сохранением исходного варианта.
7. **Упаковка набора.** Многотомный ZIP64 нельзя напрямую распаковать стандартным `zipfile`. Добавлен специализированный загрузчик одного случая; при смене структуры архива может понадобиться адаптация или полное скачивание с 7-Zip.

Ни одна из семи меток в выбранном случае не касается крайнего слоя вокселей скана. Код всё равно проверяет такие контакты: добавление нулевого padding при marching cubes создаёт искусственные торцевые крышки у структур, обрезанных границей объёма.

| Метка | Вершины | Треугольники | Компоненты маски |

| LV | 88 234 | 176 536 | 1 |

| AO | 104 734 | 209 464 | 1 |
| PA | 265 259 | 530 650 | 7 |

Метод: бинарная маска каждой метки → crop и нулевой padding → marching cubes 0.5 → компенсация crop/padding → полная affine → согласование нормалей → VTP. Ни spacing, ни смещение не применяются повторно. Все компоненты сохранены. КТ и маска не ресэмплируются.

## Следующие этапы

1. Установить соответствие `idx` из XLSX и ID файлов, подтвердить spacing, порядок осей, направления пациента и калибровку интенсивности. При подтверждении добавить явное применение исправленной геометрии с источником каждого изменения, не перезаписывая NIfTI.
2. Проверить ещё несколько случаев разных размеров, spacing и наборов меток. Сверить ориентацию и наложение с независимым просмотрщиком, затем выполнить пакетный аудит набора с таблицей проблем.
3. Исследовать неманифолдные рёбра MYO и малые компоненты. Добавить опциональную обработку с измерением изменения объёма, площади и отклонения поверхности. Затем оценить упрощение mesh и отзывчивость viewer.

Гемодинамика, обучение собственной сегментации и оформление полноценного приложения в этот этап не входят.
